# Agency CRM — панель агенції + бот для інвайтів

Софт для агенцій, що працюють на платних сайтах знайомств.

- **Веб-панель керівника** — анкети, оператори, ліцензії, статистика, налаштування сайтів, ШІ і Telegram.
- **Бот — розширення для Chrome/Edge/Brave** — працює всередині анкети жінки на сайті: бере інвайт, згенерований ШІ, і надсилає його новим чоловікам. Щойно чоловік відповів — сповіщення в браузер і Telegram, **далі переписку веде жива людина (сама жінка)**. Бот сам у діалоги не пише.

Мета — мінімум ручної роботи на розсилку, щоб людина займалась тільки тими, хто відповів.

## Найпростіше: Railway (без сервера і без паспорта, ~$5/міс)

1. railway.com → Login через GitHub → план Hobby → **New Project → Deploy from GitHub repo** → `rytmique/CRM` (гілка `main`).
2. Сервіс → Variables: `PORT=3000`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` (+ `ANTHROPIC_API_KEY`). Networking → **Generate Domain** (порт 3000). Правий клік по сервісу → **Attach Volume** → `/data`. Deploy.
3. Відкрий `*.up.railway.app` → Агенції → + Нова агенція → «Скопіювати повідомлення».

Адресу (`RAILWAY_PUBLIC_DOMAIN`) і диск (`RAILWAY_VOLUME_MOUNT_PATH`) панель бере сама. Без диска в адмінці червоне попередження. Бекап — Агенції → «⬇ Бекап». Забув пароль адміна — змінна `RESET_ADMIN_PASSWORD`, Deploy, потім видалити.

## Свій сервер (VPS) одним кліком

1. Купи VPS з Ubuntu 24.04 (IP і пароль root прийдуть листом).
2. Двічі клікни **`deploy.bat`** → 5 питань → чекай «ГОТОВО» з адресою панелі.
3. Агенції → **+ Нова агенція** → **Скопіювати повідомлення** → надішли клієнту.

Оновити панель — знову `deploy.bat` (Enter). Бекап — `backup.bat` (файл у папці `backups`).

## Запуск на Windows — подвійний клік

| Файл | Що робить |
|---|---|
| `start.bat` | Робоча панель на `http://localhost:3000`. Перший запуск сам встановлює залежності; відкриває браузер. Логін адміна — у консолі й у `data\admin-login.txt` (або задайте `ADMIN_EMAIL` / `ADMIN_PASSWORD` у `.env`). |
| `start-test.bat` | **Тестовий стенд** на `http://localhost:3001`: окрема база `data-test`, готова агенція, оператор, 3 анкети на демо-сайті, ліцензії і 2 тижні демо-статистики. Робоча база не зачіпається. `start-test.bat reset` — стерти тестову базу й почати з нуля. |

Входи тестового стенда (пароль `test12345`): `admin@test` — адмін платформи, `owner@test` — керівник, `operator@test` — оператор для розширення. Розширення для стенда беріть з його ж панелі (Розширення → Завантажити) — там уже вшита адреса `:3001`.

Потрібен лише [Node.js 22 LTS](https://nodejs.org) або новіший — якщо його немає, .bat підкаже і відкриє сторінку завантаження. Налаштування (порт, ключ Claude тощо) — у файлі `.env` поруч, зразок у `.env.example`. Якщо панель уже запущена, повторний запуск просто відкриє її в браузері.

На macOS / Linux: `npm start` і `npm run test-stand`.

## Тест-режим бота

У розширенні галочка **🧪 Тест-режим**. Бот проходить увесь шлях на справжньому сайті, але **не натискає «Надіслати»**:

1. знаходить чоловіків на сторінці пошуку і показує, що бачить (ім’я, вік, ID);
2. на 3 чоловіках відкриває чат, вставляє текст, підсвічує кнопку «Надіслати» — і стирає текст;
3. перевіряє «Наступну сторінку» або догрузку стрічки при прокрутці;
4. відкриває вхідні й показує, скільки діалогів і непрочитаних бачить.

Нічого не надсилається, денний ліміт не витрачається; на сервер іде лише підсумок тесту (✓ або список проблем) — для майстра підключення. В кінці — «Тест пройдено ✓» або список, що саме поправити в налаштуваннях сайту. Ідеально для підключення нового сайту.

## Швидкий старт (вручну)

Потрібен Node.js 22.13+ (SQLite вбудований, нічого компілювати не треба).

```bash
git clone https://github.com/rytmique/CRM.git && cd CRM
npm install
ADMIN_EMAIL=admin@local ADMIN_PASSWORD=admin12345 npm start
# панель: http://localhost:3000
```

1. Увійдіть як адмін платформи → **Агенції → + Нова агенція** (одразу можна видати ліцензії).
2. Вийдіть і увійдіть як керівник агенції.
3. **Оператори** → додайте оператора. **Анкети** → додайте анкету, виберіть сайт, оператора і ліцензію.
4. **Розширення** → завантажте архів (адреса панелі вже вшита), встановіть «Завантажити розпаковане».
5. У розширенні: логін оператора → анкета → **▶ Старт**.

Для тесту без реального сайту є вбудований **демо-сайт** (`/demo-site/`): він додається до кожної нової агенції як сайт «Демо-сайт (для тесту)». Чоловіки там фейкові, ~40% «відповідають» через кілька секунд — видно весь цикл.

### Сервер (Docker + автоматичний HTTPS)

```bash
curl -fsSL https://get.docker.com | sh
git clone https://github.com/rytmique/CRM.git /opt/agency
cd /opt/agency
cp .env.example .env && nano .env      # DOMAIN, PUBLIC_URL, ADMIN_EMAIL, ADMIN_PASSWORD, ANTHROPIC_API_KEY
docker compose up -d --build            # панель + Caddy (HTTPS-сертифікат для DOMAIN отримується сам)
```

Оновлення: `git pull && docker compose up -d --build`. Дані — у `./data`. Скинути пароль будь-кого: `docker compose exec app node server/reset-password.js email@x НовийПароль`.

## Ролі

| Роль | Що бачить |
|---|---|
| **Адмін платформи** (постачальник софту) | Агенції (створити / призупинити), ліцензії: видати N ключів на M днів, продовжити, відкликати |
| **Керівник агенції** | Бачить і контролює все: дашборд і конверсію по анкетах/операторах, анкети, оператори, ліцензії, журнал, сайти, налаштування. Тільки він видаляє анкети й сайти |
| **Оператор** | Сам створює й редагує **свої** анкети (ліцензія береться з вільних автоматично), додає й навчає сайти, сценарії й шаблони; запускає бота в розширенні |

Сайт може змінювати той, хто його додав, і оператори, чиї анкети на ньому працюють; шаблон — його автор. Керівник — усе.
Призупинена агенція або відкликана / прострочена ліцензія — бот не запускається, і це видно одразу в розширенні.

## 🚀 Підключення «за руку»

Новий користувач одразу потрапляє в **Підключення**: 6 кроків по одному (сайт → анкета → розширення → навчити → 🧪 тест → ▶ старт).
Кожен крок сам ставить ✓, коли його зроблено (навіть якщо це зроблено в розширенні) — сторінка оновлюється кожні 4 с.
На дашборді, доки бот не надіслав перший інвайт, висить банер «Продовжити →».

## 🎯 Навчити бота кліками (без селекторів)

1. Відкрийте сайт знайомств на сторінці пошуку чоловіків.
2. Значок розширення → **🎯 Навчити бота на цьому сайті**. Праворуч з’явиться панель.
3. «Картка чоловіка» → **🎯 Вибрати** → клікніть на порожнє місце будь-якої картки. Бот сам знайде ID, ім’я, вік і кнопку «Написати» — перевірте зелені підказки.
4. Натисніть «Написати» на сайті (як зазвичай), потім вкладка **Відправка**: виберіть поле вводу і «Надіслати».
5. Відкрийте сторінку будь-якого чоловіка → вкладка **Його сторінка** → **📍 Ця сторінка** (потрібно для повторних спроб). Панель сама переходить разом із вами.
6. **Кнопки й ознаки**: напишіть «Лайк» → **+ 🎯 Додати** → клікніть кнопку лайка. Так само ознаки в картці («Онлайн», «Преміум»).
7. **💾 Зберегти** → у розширенні 🧪 тест.

Поки вибираєте, кліки по сайту нічого не роблять (не надсилають і не переходять). Esc — скасувати.

## Сценарій: що бот робить з кожним чоловіком

**Сайти → ⚙ Сценарій.** Стандарт: інвайт → через 24 год повторне → через 48 год ще одне → без відповіді чоловік зникає зі списку. Щойно відповів — бот зупиняється, далі пише жива людина.

- **Кроки**: у кожному — дії по черзі: ✉ повідомлення (інвайт / повторне від ШІ / свій текст з варіантами через `---`), 👆 натиснути навчену кнопку (лайк, підморгнути…), 👀 переглянути профіль (з шансом %), ⏸ пауза.
- **Кому писати**: тільки / крім країн, тільки з ознакою (напр. «Онлайн»), пропускати з ознакою. Вік — в анкеті.
- **Обережність**: робочі години, макс. повідомлень на годину, перерви кожні N повідомлень, друк по літері. Числа випадково «гуляють».
- Повторні тексти ШІ пише один раз на анкету; змінити — **Анкета → Повторні повідомлення**.
- **Після відповіді** (стандарт: 10 спроб, 48 год тиші, далі кожні 48 год): відповів — пише жива людина; якщо він знову замовк, бот сам нагадає про себе коротким повідомленням (3 варіанти від ШІ, **Анкета → Після відповіді**). Кожна нова позитивна відповідь додає ще 10 спроб. «Not interested / не пиши / fake» — бот більше не пише. Без відповіді на всі нагадування — чоловік зникає зі списку.
- **Розклад і темп**: робочі дні; робочі години кількома вікнами (`9-13, 15-23`); «Рівномірно на весь робочий день» — денний ліміт розтягується до кінця робочого часу, а не витрачається за пів години.
- **⏱ Паузи** (кожна — випадково «від–до», у секундах): між чоловіками, «подумати» перед текстом, між діями кроку (лайк → повідомлення), перед наступною сторінкою; перерва кожні N повідомлень на X–Y хв; швидкість друку (знаків/хв).
- **✉ Листи**: у дії «Написати повідомлення» вибирається **💬 у чат** або **✉ листом**. Текст «Лист» ШІ пише один раз на анкету (700–1200 символів, тема — перший рядок), змінити — **Анкета → ✉ Лист**. Навчити форму листа: 🎯 → вкладка **Листи** (конверт, тема, поле, «Надіслати», лічильник).
- **Лічильники сайту** («Залишилося 9 повідомлень / 2 листи»): якщо навчити їх (🎯 → Відправка / Листи), бот читає число і при 0 цьому чоловіку більше не пише — спроби не марнуються.
- **Кнопка «Перекласти»**: якщо сайт перекладає текст, навчіть її (🎯 → Відправка) — бот натисне після тексту й зачекає переклад.
- Денний ліміт рахує всі повідомлення (і перші, і повторні, і нагадування). Нагадування і повторні йдуть першими — це теплий трафік.
- Журнал показує статус кожного: надіслано / чекає повтору / не відповів · прибрано / відповів (+ його текст, «не цікаво», скільки нагадувань лишилось).

## 🖥 Сайти-«робочі столи» (список чатів + чат + підказки сайту)

Деякі сайти — це один екран оператора: ліворуч список чатів, праворуч відкритий чат, збоку — підказки сайту «Please write him message / letter». Бот уміє так:
- **Підказки сайту** (🎯 → вкладка «Підказки»): бот бере чоловіків звідси першими, після людської паузи (стандарт 20–90 с), відкриває чат кліком по підказці й пише **в чат або листом — як просить підказка**.
- **Клік по самій картці** відкриває чат (`@self` — бот ставить сам, коли ви клікаєте саму картку як «Написати»).
- **Запобіжник**: бот пише, лише якщо в шапці відкритого чату ім’я / ID саме цього чоловіка. Відкрився чужий чат — нічого не друкує.
- **ID з шапки чату**, якщо в картці його немає. **Повторні** — через пошук за ID у полі сайту (🎯 → «Його сторінка» → «Пошук чоловіка за ID»).
- Відповіді знаходяться навіть без ID у списку — за ім’ям («Gene, 65» → Gene).
- Між чоловіками інколи просто гортає список, як людина (стандарт 30 %; нічого не відкриває, щоб непрочитані лишались непрочитаними).

Демо такого екрана: `/demo-site/desk.html` (е2е-тест проганяє на ньому весь цикл).

## ⏰ Автопілот

Галочка **⏰ Автопілот** у вікні розширення: бот сам вмикається в робочі дні й години зі сценарію і сам вимикається після. На новий день — свіжий ліміт. Натиснули ■ Стоп у робочий час — сьогодні автопілот більше не вмикає (до наступного робочого дня). Браузер має бути відкритий, а анкета — залогінена на сайті.

## ⭐ Найперспективніші чоловіки першими

Бот запам’ятовує (анонімно, на всю платформу), які ознаки з картки чоловіка — країна, вік, «онлайн»/«преміум», слова з опису — частіше дають відповідь.
Коли даних достатньо (60+ інвайтів на платформі), бот на старті робить **🔭 розвідку**: переглядає 3 сторінки, сервер ставить кожному бал, і найкращим бот пише першими (на їхній сторінці), а потім — усім іншим. На кожній сторінці теж спершу ті, в кого бал вищий.

## 🧠 Інвайти, що вчаться

- В анкети одночасно **кілька варіантів інвайту** (стандарт 3). Бот частіше шле той, на який більше відповідають (Thompson sampling), нові теж отримують шанс.
- Раз на 30 хв сервер порівнює варіанти: явно слабший (≥ 40 надсилань і ≥ 90 % впевненості) вимикається, ШІ пише новий, беручи за зразок найкращий.
- **Спільна пам’ять платформи** (адмін → «Пам’ять ШІ»): короткі уроки з реальних відповідей усіх агенцій — з цифр (довжина, питання в кінці, emoji, {name}) і від ШІ (порівнює найкращі й найгірші інвайти без імен і міст). Уроки йдуть у кожен промт інвайту. Агенція може вимкнути: Налаштування → Навчання інвайтів.
- В анкеті видно кожен варіант: надіслано / відповіли / % і 🏆 найкращий; можна додати свій, вимкнути, повернути.

## 🛑 Капча, «забагато запитів», розлогінило

Бот нічого не обходить: він помічає капчу (reCAPTCHA, hCaptcha, Turnstile, «verify you are human»), «too many requests» або сторінку входу, **зупиняється**, шле сповіщення «потрібна людина» в браузер і **в Telegram** (оператору й агенції, раз на 10 хв) і чекає. Людина розв’язує у вкладці — бот продовжує сам, але з довшими паузами (×1.5, до ×3). За годину ніхто не розв’язав — бот зупиняється.

### Шаблони сценаріїв
- У редакторі сценарію: **⬇ Завантажити** готовий (⭐ Стандарт / М’який / Активний) або свій шаблон, **💾 Зберегти як шаблон**.
- **Сайти → Шаблони сценаріїв**: створити, змінити, видалити.
- Окремій анкеті можна дати свій сценарій: **Анкета → Редагувати → Сценарій** (інакше діє сценарій сайту).
- Кнопки в шаблоні посилаються на навчені кнопки за назвою-ключем; якщо на сайті такої кнопки немає — дія пропускається.

## 📎 Файли до повідомлень (фото, відео)

1. **Анкета → 📎 Файли до повідомлень → + Додати файли з ПК** (jpg/png/webp/heic, mp4/mov, аудіо, pdf; до 15 МБ, до 30 на анкету).
2. Біля кожного файлу позначте кроки, на яких його слати (крок 1 = інвайт, 2 = перше повторне…).
3. У сценарії в дії «Написати повідомлення»: **усі файли кроку** / **один випадковий** / **без файлів**.
4. Навчіть бота скрепку: 🎯 → Відправка → «Кнопка «Прикріпити файл»». Бот не відкриває вікно вибору файлу — підставляє файл сам (через поле файлу сайту, перехоплення скрепки або перетягування).
5. 🧪 Тест покаже, чи знайдено, куди прикріпити.

Файли лежать на сервері поруч з базою (`data/media`, на Railway — у Volume) і в бекап бази не входять.

## Як працює бот

1. Бере конфіг анкети: активний інвайт (якщо немає — генерує ШІ), налаштування сайту, денний ліміт, паузи.
2. Відкриває сторінку пошуку, збирає чоловіків з картки (ID, ім’я, вік, країна).
3. Сервер відсіює тих, кому ця анкета вже писала (ніколи двічі), невідповідний вік і обрізає по денному ліміту.
4. Для кожного: «Написати» → вставляє персоналізований текст (`{name}` → ім’я; нікнейми типу `john_1985` пропускаються) → «Надіслати» → чекає підтвердження → звітує на сервер.
5. Пауза між повідомленнями — випадкова в межах «від–до» (налаштовується).
6. Кожні N повідомлень і в кінці відкриває вхідні в фоновій вкладці і шукає непрочитані → нові відповіді йдуть у статистику + сповіщення (браузер, Telegram жінці / оператору / агенції).
7. Після розсилки або ліміту бот залишається в режимі «стежу за відповідями» (перевірка кожні 3 хв).

Пауза анкети в панелі зупиняє бота за ~30 с. 5 помилок поспіль — бот зупиняється і пише, що не так (найчастіше селектори сайту).

## Налаштування сайту (адаптер)

Під кожен сайт знайомств у розділі **Сайти** задаються CSS-селектори — без зміни коду:

| Поле | Приклад | Що це |
|---|---|---|
| URL пошуку | `https://site.com/search` | звідки бот стартує |
| Картка | `.man-card` | один чоловік у видачі |
| ID | `@data-id` або `a.profile@href` | унікальний ID |
| Ім’я / Вік / Країна | `.name` / `.age` / `.country` | дані для персоналізації і фільтра |
| Наступна сторінка | `a.next` | пагінація |
| «Написати» | `.btn-write` | кнопка в картці |
| Поле вводу | `#chat textarea` | textarea / input / contenteditable |
| «Надіслати» | `#chat .send` | якщо порожньо — Enter |
| Підтвердження / помилка | `.sent-ok` / `.error` | щоб знати, що лист пішов |
| URL вхідних, діалог, непрочитане, ID, ім’я | `.dialog`, `.unread` | пошук відповідей |

Формат витягування: `.sel` — текст елемента, `.sel@attr` — атрибут елемента, `@attr` — атрибут самої картки.
Перевірка: відкрийте сторінку пошуку і натисніть 🔍 у розширенні — покаже, скільки чоловіків бот бачить і приклади.

## Підключення свого сайту — покроково

Код міняти не треба: сайт описується CSS-селекторами в панелі. 10–15 хвилин у Chrome DevTools.

**0. Де працює панель.** Розширення ходить на сервер панелі. Для одного комп’ютера достатньо `npm start` локально. Для команди — VPS з доменом і HTTPS, `PUBLIC_URL=https://ваш-домен`; тоді в архіві розширення з панелі вже буде правильна адреса.

**1. Знайдіть селектори.** Залогіньтесь в анкету, відкрийте пошук чоловіків, натисніть F12.
- Правий клік по картці чоловіка → «Перевірити» (Inspect). Піднімайтесь по дереву вгору, поки не підсвітиться вся картка, і подивіться її `class` або `data-…` атрибути.
- Перевірте в Console: `document.querySelectorAll('.ваш-селектор').length` — має дорівнювати кількості чоловіків на сторінці.
- Беріть стабільні назви (`.profile-card`, `[data-user-id]`). Не беріть `div:nth-child(3)` і «абракадабру» на кшталт `.sc-1x2y3z` — вона міняється з кожним оновленням сайту.

| Поле | Що знайти | Перевірка в Console |
|---|---|---|
| Картка | блок одного чоловіка | `document.querySelectorAll('.card').length` = кількість чоловіків |
| ID | посилання на його профіль у картці: `a@href` (з `/profile/123456` бот візьме `123456`), або `@data-id` | `document.querySelector('.card a').href` |
| Ім’я, вік, країна | елементи всередині картки | `document.querySelector('.card .name').textContent` |
| Наступна сторінка | кнопка/посилання пагінації; **якщо сторінок немає і список догружається при прокрутці — залиште порожнім** | — |
| «Написати» | кнопка в картці (може відкривати віконце **або** вести на сторінку профілю/чату — підтримується обидва варіанти) | `document.querySelector('.card .write')` |
| Поле вводу, «Надіслати» | у віконці чату або на сторінці профілю | клацніть «Написати» вручну, потім Inspect |
| Підтвердження відправки | що з’являється після відправки («Sent», галочка). Не знайшли — залиште порожнім | — |
| Вхідні | URL сторінки діалогів, елемент діалогу, ознака непрочитаного (`.unread`, бейдж «new»), ID — посилання на чоловіка | має дати **те саме число**, що ID у пошуку |

**2. Збережіть.** Панель → Сайти → «+ Додати сайт» → заповніть → Зберегти. В анкетах виберіть цей сайт.

**3. Перевірте.** У браузері з розширенням відкрийте сторінку пошуку на сайті → у розширенні виберіть анкету → 🔍. Має бути: «Бачу чоловіків: 20. Наприклад: John 45 [123456]…». Якщо 0 — неправильна картка; якщо ID порожні або дивні — неправильний ID.

**3½. Прогоніть 🧪 Тест-режим** — він перевірить відкриття чату, вставку тексту, кнопку «Надіслати», пагінацію і вхідні, нічого не надіславши.

**4. Перший справжній запуск — з лімітом 3–5 на день.** Подивіться очима: відкривається чат, вставляється текст, натискається «Надіслати», бот повертається до списку. Усе гаразд — піднімайте ліміт.

**Якщо щось не так** (помилка видна в лозі розширення і в Журналі):

| Помилка | Що поправити |
|---|---|
| картку чоловіка не знайдено | селектор картки або ID |
| кнопку «Написати» не знайдено | «Написати» має бути **всередині** картки |
| поле вводу не з’явилось | «Поле вводу»; якщо чат відкривається у вбудованому вікні iframe — поки не підтримується, напишіть розробнику |
| не дочекались підтвердження | «Ознака успішної відправки» — виправте або очистіть поле |
| сайт: … | сайт сам показав помилку (немає кредитів, ліміт, капча) — бот зупиниться після 5 помилок поспіль |
| відповіді не рахуються | «Ознака непрочитаного» або ID у вхідних дає інше число, ніж у пошуку |

## ШІ (Claude)

Інвайт пишеться з полів анкети: «про себе», інтереси, кого шукає, тон, мова, нотатки + загальні інструкції агенції.
Правила промпту: від першої особи, конкретика з анкети, одне легке питання в кінці, 250–450 символів, `{name}` у привітанні, **без контактів, посилань, месенджерів, грошей, інтиму і обіцянок зустрічі**. Відповідь перевіряється сервером; якщо порушує правила — одна повторна спроба, далі помилка.

- Модель за замовчуванням `claude-opus-5-5` (у Налаштуваннях можна вибрати Sonnet 5.5 / Haiku 5.5 — дешевше).
- Ключ: `ANTHROPIC_API_KEY` на сервері або окремо для агенції в Налаштуваннях (зберігається в БД, у UI маскується).
- Увімкнено серверний `fallbacks: "default"`: якщо модель відмовить, запит автоматично повторюється на рекомендованій резервній моделі.
- **Без ключа** система теж працює — інвайти збираються локальним шаблоном з полів анкети.
- **Майстер-промт**: Налаштування → «Майстер-промт для інвайтів» — повністю замінює вбудований промт для всієї агенції. Змінні `{her_name}`, `{her_age}`, `{her_city}`, `{her_country}`, `{about}`, `{interests}`, `{looking_for}`, `{tone}`, `{notes}`, `{language}`, `{profile}`; кнопка «Перевірити на анкеті» генерує приклад без збереження. `{name}`, `{age}`, `{country}` лишаються для даних чоловіка.
- **Свій промт анкети**: у формі анкети — перекриває майстер-промт. Порядок: анкета → агенція → вбудований. Фільтр контактів і посилань діє за будь-якого промту.

## Статистика

- Сьогодні: інвайти, помилки, відповіді, конверсія.
- За 7 / 14 / 30 днів: графіки інвайтів і відповідей по днях, конверсія (з інвайтів періоду — скільки отримали відповідь).
- По анкетах і операторах, стрічка останніх відповідей з кнопкою «Чат».
- Журнал усіх відправок з фільтрами (анкета, відповіли / без відповіді / помилки, пошук).
- «Сьогодні» рахується за часовим поясом агенції (Налаштування).

## Структура

```
server/        Express + node:sqlite
  routes/      auth, admin, operators, profiles (+інвайти), licenses, sites, settings, stats, bot (API розширення)
  ai.js        генерація інвайтів/повторних/нагадувань через Claude + шаблон без ключа, «не цікаво» у відповіді
  scoring.js   бал чоловіка з ознак картки (спільна анонімна статистика платформи)
  learning.js  варіанти інвайтів, Thompson sampling, оптимізатор, спільна пам’ять (уроки)
web/           панель (SPA без збірки, світла/темна тема, мобільна верстка)
extension/     розширення MV3: background (оркестрація), content (робота зі сторінкою), popup
demo-site/     тестовий сайт знайомств для перевірки бота
test/          api.test.js (node:test), e2e.mjs (Playwright: панель + реальний прогін розширення)
```

## API розширення (коротко)

|---|---|---|
| GET | `/api/bot/profiles` | анкети оператора + ліцензія + лічильники |

| POST | `/api/bot/profiles/:id/pool` | розвідка: чоловіки з кількох сторінок → бал |
