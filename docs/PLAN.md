# План: сканер → бот під звіт → реальні тести

Головне правило: **замовник нічого не налаштовує.** Максимум — кілька кнопок за зміну. Усе налаштування робимо ми по звіту.

**Сервера ще немає** (Railway не розгорнуто). Тому сканер — **окреме маленьке розширення** (`scanner/`): без входу, без сервера, без коду бота.
Доставка: zip → замовник ставить його один раз (chrome://extensions → Режим розробника → «Завантажити розпаковане») → звіт скачує сам і скидає користувачу.
Сервер (Railway) розгортаємо перед Етапом 3 — він потрібен уже самому боту.

## Етап 1. Нічний сканер («Вивчити сайт»)

**Замовник робить:**
1. Один раз ставить сканер із zip (4 кроки, інструкція з картинками в архіві).
2. На початку зміни: відкриває сайт → значок сканера → **🔍 Вивчити сайт**. Далі працює як завжди, всю ніч.
3. Зранку: значок сканера → **📦 Скачати звіт** → скидає zip користувачу.

**Що робить сканер (сам, без кнопок):**
- **Тихий запис** усю зміну: на кожну нову сторінку чи стан (чат, лист, підказки, перемикач жінок, переклад, скрепка, після «Надіслати») зберігає структуру елементів. Сам нічого не натискає.
- **Короткий безпечний обхід** на старті (5–10 хв) в окремій фоновій вкладці: меню, вкладки, списки. Не натискає «надіслати / подарунок / оплата / видалити». Не відкриває непрочитані чати. Якщо сайт поводиться дивно (друга вкладка, розлогін, капча) — обхід зупиняється, тихий запис триває.
- **Розпізнає ролі** з балом достовірності: підказки «write him», чат, шапка чату (ім’я/ID), поле вводу, «Надіслати», переклад, фото/відео/аудіо, лист, лічильники «Залишилося N», перемикач жінок, непрочитані, капча.
- **Що змінюється після дій оператора**: що з’явилось після «Надіслати» (ознака відправки), як змінились лічильники. Довжини прев’ю в списку чатів (для правила 5 символів) — лише числа.
- **Пробний прогін** раз на годину: чи бачить бот підказки, чи читає ID у шапці. Нічого не надсилає.
- Усе зберігається локально в браузері, переживає перезапуск. Розмір обмежено (дублікати структур не зберігаються).

**Інший бот у оператора:** оператор може паралельно працювати зі своїм старим ботом (інше розширення). Сканер йому не заважає: жодних кліків, переходів, нових вкладок, фокусу чи змін сторінки; легкий; витримує сплески дій. Вставки інших розширень у сторінку позначає як «не сайт». Знеособлено записує, що й у якому порядку натискає той бот — корисно для нашого.

**Що в звіті (безпечно для NDA):** структура сторінок (теги, класи, атрибути, розміри, стани), CSS + XPath, ролі з достовірністю, події «дія → що змінилось», результати пробних прогонів, помилки, схеми екранів (блоки + ролі, не фото).
**Чого немає:** імен, ID, текстів листування, фото, адрес з ID, cookies, паролів, токенів. Перед скачуванням — автоперевірка на імена, email, телефони, довгі числа.

**Готово, коли (на демо-сайті, автотести):**
- сканер сам знаходить усе, що зараз навчають кліками (робочий стіл + пошук);
- ловить ознаку відправки з тихого запису;
- у звіті немає жодного демо-імені / ID / тексту;
- жодного кліку по «пастках» (демо-кнопки «Send gift», «Delete», «Buy»);
- витримує кілька годин, перезавантаження сторінки й SPA-переходи.

## Етап 2. Бот під звіт

1. **Профіль сайту** з реального звіту → «готовий сайт» на сервері. Бот бере його сам при старті (замовнику не треба оновлювати бота при правках).
1а. **Оновлення бота в один клік** (замовник один раз показує папку бота → далі «🔄 Оновити» → «Дозволити» → бот сам замінює файли й перезапускається). Більшість правок — даними з сервера, без оновлення коду.
2. **Демо-копія** реального сайту за звітом — щоб автотести ганяли саме ту структуру.
3. **Нуль налаштувань:** анкети бот бере з перемикача жінок на сайті; сценарій і ліміти за замовчуванням; ключ ШІ наш; налаштування сховані.
4. **Вікно оператора** (темна бокова панель): START / STOP, до 5 жінок зі статусами, короткий журнал, «чого бракує» простими словами.
5. **Інвайти:** під кожного чоловіка з його видимого профілю, 3 категорії (особисте / місто / флірт), перші 5 символів — окремий хук з перевіркою; промпт вшитий. *(Починаю паралельно з Етапом 1 — від сайту не залежить.)*
6. **5 анкет:** окремі стан, черга, журнал, стоп на кожну. Одночасно — якщо звіт покаже, що сайт це дозволяє; інакше чесна черга.
7. **Самоперевірка** перед кожним стартом; сайт змінився → бот сам вмикає тихий запис і повідомляє нас.

**Готово, коли:** повний прогін на демо-копії зелений; пробний прогін (без відправки) по реальному профілю проходить.

## Етап 3. Реальні тести

Кожен крок — одна зміна, замовник тисне лише START; зранку — 📦 звіт.
1. **Сухий прогін:** бот робить усе, крім «Надіслати». Перевіряємо: та сама жінка, той самий чат, правильне поле.
2. **Обережний:** 1 жінка, 10–20 інвайтів, низькі ліміти. Дивимось помилки, відповіді, якість текстів.
3. **Повний:** до 5 жінок, звичайні ліміти.

**Критерії:** жодного повідомлення не тому чоловіку / не від тієї жінки; жодного зависання; кожна помилка зрозуміла; тексти замовник схвалив. STOP працює завжди; щось дивне — бот сам стає на паузу.

## Ризики
- Сайт може не пускати другу вкладку → безпечний обхід вимкнеться, лишиться тихий запис (його достатньо).
- Частина речей видна лише чоловікам (прев’ю 5 символів у них) → перевіряємо по довжинах у списку чатів і на першій реальній відправці.
- Мало даних про чоловіка → категорії «місто» й «особисте» по імені/віку/країні; інтереси — якщо видно його профіль.
