Дата: листопад 2026. Код: `main` @ 6728f0b. API-тести: **19/19 зелені** (`npm test`). E2E під час аудиту не запускався (≈30 хв), останній зелений прогін — у попередній сесії.

## 2. Чому зараз складно оператору
1. **Ручне навчання** (`extension/picker.js`): 52 поля адаптера (`SITE_FIELDS`). Для «робочого столу» треба проклікати підказки, шапку чату, конверт, пошук, вхідні, перемикач жінок. Новачок без допомоги не впорається.
2. Готовність сайту перевіряється лише по 3 полях (`siteReady`); що зламалось після оновлення сайту — видно тільки з помилок під час роботи.
3. Головне вікно — popup на 360 px: логін, анкета, тест, автопілот, швидкість, ротація, навчання в одному місці.

## 3. П’ять анкет — як насправді
- `background.js` має **один** глобальний стан (`state`, `running`, `stopRequested`, `her`). Одночасно працює **одна** анкета.
- 🔁 «Зміна анкет» (`rotateProfiles`) — це **послідовне перемикання** жінки на сайті, коли в поточної немає роботи або ліміту. Паралельності немає.
- Чи можлива справжня паралельність, залежить від сайту: якщо активна жінка одна на всю сесію браузера (перемикач `herSwitch`), то вкладки заважатимуть одна одній. Додатково Chrome гальмує таймери у прихованих вкладках, а друк по літері йде таймерами сторінки.
- **Висновок:** незалежні стани, черги, журнали, паузу й стоп на кожну анкету зробити можна і треба. Чи можуть 5 анкет справді діяти одночасно — перевіряємо на реальному сайті через Inspector (Етап 2). Не імітуємо.

## 5. Прийняті рішення (за замовчуванням)
1. Надсилання автоматичне, як зараз. Межі не міняються: не обходимо капчу й антибот, не підробляємо відбиток браузера, не чіпаємо сесії й токени.
2. Стек лишається: чистий JS без збірки (ТЗ дозволяє). Новий код розкладаємо по модулях: `extension/modules/*.js`, service worker як ES-модуль.
3. Ключ ШІ: локально в розширенні (`chrome.storage.local`), ключ команди на сервері — запасний.
4. Site Profile: локально + обмін очищеною структурою з командою через панель (без текстів, імен, ID чоловіків, cookies, токенів).
5. Медіа: лишається на сервері (спільне для команди); додаємо категорії. Локальна копія — кеш у IndexedDB.
6. Скріни Inspector: лише локально, з маскуванням тексту; непрочитані чати сканер не відкриває (інакше зникне позначка «нове»).
7. Location: за замовчуванням тільки загальні теми міста й регіону, без вигаданих закладів і подій; пошук в інтернеті — окрема опція пізніше.
8. 5 символів: рахуємо символи (графеми), без пробілу чи розділового знака на початку. Як рахує сам сайт — перевірити на реальному.
9. Ручне навчання (picker) лишається в Advanced як запасний варіант.

## 6. План етапів (кожен — тести + коміт)
1. **Audit** — цей файл.
2. **Inspector + Site Profile**: автоскан поточної сторінки й безпечних розділів (посилання / вкладки меню; небезпечні кнопки лише описуються). Класифікація ролей (картка, шапка чату, поле вводу, «Надіслати», скрепка, підказки, вхідні, перемикач жінок…) з балом достовірності. Збереження, порівняння сканувань, експорт без особистих даних. На демо (`search.html`, `desk.html`) Inspector має сам знайти те, що зараз навчають кліками.
3. **Adapter**: Assistant бере Site Profile → конфіг сайту; перевірка перед роботою; зміна структури → пауза + «пересканувати».
4. **AI invitations**: локальна AI-конфігурація + перевірка ключа; 3 категорії; Preview Hook; варіанти, перегенерація, редагування в панелі.
5. **Multi-profile**: до 5 контекстів (стан, черга, журнал, пауза/стоп). Справжня паралельність — лише якщо Етап 2 покаже, що сайт це дозволяє; інакше чесний режим черги з поясненням.
6. **Operator UX**: темна бокова панель: статуси, 5 анкет, START ALL / STOP ALL, «чого бракує».
7. **Test & build**: e2e, збірка, інструкція.

## 7. Невідомо / треба від користувача
- Експорт Site Profile з реального сайту після Етапу 2 (без особистих даних) — без нього адаптер під реальний сайт = припущення.
- Чи активна жінка на сайті одна на сесію (важливо для 5 анкет).
- Як сайт рахує 5 символів прев’ю.
