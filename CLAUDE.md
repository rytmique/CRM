## Що це за продукт
Софт для агенцій, які працюють на платних сайтах знайомств. Дві частини:
1. **Веб-панель** (`web/` + `server/`): адмін платформи → агенції, ліцензії, «Пам’ять ШІ»; керівник агенції (owner) → бачить і контролює все, конверсія, оператори, ліцензії, налаштування; оператор → сам створює/редагує свої анкети, додає й навчає сайти, сценарії (видаляти анкети/сайти — тільки owner).
2. **Бот = розширення Chrome MV3** (`extension/`): працює в браузері оператора всередині анкети жінки на сайті знайомств. Знаходить чоловіків, пише їм інвайт (текст генерує ШІ Claude), робить повторні спроби за сценарієм, ловить відповіді у вхідних. Коли чоловік відповів — бот зупиняється, далі пише жива людина (сама жінка).

Мета — обслужити максимум чоловіків з мінімумом ручної роботи, не «палячи» трафік (людський темп, ліміти, рівномірно на день). Користувач хоче: дуже кастомно, дуже легко й зрозуміло (новачок має пройти підключення сам), ефективно, не впиратись у капчі.

## Як працює бот (коротко)
1. `config` → інвайт(и): до `ai.variants` (3) варіантів у ротації (оптимізатор доповнює), повторні тексти, нагадування (followups.step=100), сценарій, ліміти, часовий пояс, `ranking`.
2. Старт: вручну або ⏰ автопілот (alarm щохвилини: робочі дні/години → старт; поза ними → стоп; новий день → перезапуск; ручний Стоп → heldDay до завтра).
3. Якщо `ranking.ready` (60+ інвайтів на платформі) і є `manUrl` → **розвідка**: 3 сторінки → `/pool` → `/pool/next` (топ 30 % з балом > 0) → пише їм на їхній сторінці.
4. Цикл: робочий час → **спершу нагадування й повторні** (`/due`) → пошук → `scan` → `/filter` (дедуп, вік, країни, ознаки, ліміт; найкращі першими, коли ranking готовий) → крок 1 (`runActions`; варіант інвайту — Thompson) → `/sent` → пауза (рівномірно на день / перерва / ліміт на годину).
5. Перед кожною сторінкою/чоловіком — `guard()`: капча / «too many requests» / розлогінило → статус `blocked`, сповіщення, чекає людину (до 1 год), далі паузи ×1.5.
6. Стан чоловіка в `messages`: `step`, `stage` (active/replied/done), `next_at`, `bonus_left`, `reply_mood`. Відповів позитивно → `replied`, +`afterReply.attempts` (10) нагадувань; мовчить `silenceHours` (48) → нагадування кожні `everyHours`; ті самі «непрочитані» знову → лише відкладає. «Не цікаво» → bonus 0. Нагадування скінчились → `done`.
7. Повідомлення (`writeHere`): ✉ лист → клік «Лист» → лічильник сайту (0 → `exhausted`, чоловік `done`) → тема → текст (думає `think`, друкує `typeSpeed`) → файли → «Перекласти» → «Надіслати». Між діями кроку — `actionGap`, між сторінками — `pageGap`. Тест-режим: нічого не натискає/не надсилає, на сервер — лише підсумок `/test`.
   Тексти в followups: step 2.. — повторні, 100 — нагадування, 200 — лист.
10. Оплата: heartbeat з `active` (running/waiting, не тест) → `bot_activity` секунди між двома активними «пульсами» (≤150 с). Фіксується на того, хто запустив бота.
11. Тест: швидкий (`runTest`) + `fullDryRun` (до 15 чоловіків, dry, нічого на сервер); 📋 `buildReport` + `maskText` (без імен/ID/адрес).
9. Сайт-«робочий стіл» (немає `card`, є `taskItem`): цикл = повторні (`/due`, без `manUrl` — `findMan` за ID у полі пошуку) → `processTasks` (підказки сайту: реакція `react`, `openTask` клік → `waitChat` перевіряє шапку → ID з `chatId` → `/filter` з `via` з підказки → пише) → чекає нових підказок 1–2.5 хв. `writeHere` на таких сайтах завжди перевіряє, що відкритий чат його (`chatName`/`chatId`). Відповіді без ID — сервер матчить за ім’ям.
12. 🔁 Зміна анкет — тепер ЗАВЖДИ (1.5.0, див. «сьома сесія»); стара схема (галочка в popup, `rotate`): `run(..., {rotate})` повертає 'limit'|'idle'|'stopped' → `rotateProfiles` бере наступну анкету того ж сайту (ліцензія, active, лишок ліміту; idle — відпочинок 10 хв, limit — 24 год) → `ensureHer` (herUrl з {pid} або клік herSwitch → herItem за herItemId/ім’ям → перевірка herCurrent). `writeHere` не пише, якщо `chatHer` показує іншу жінку. ID жінки = `profiles.site_profile_id`.
13. Швидкість: popup `speed` 1–5 → `speedMul` (×2 … ×0.35) на всі паузи й друк. Стоп: `stopRequested` + `window.__agencyBotStop` у сторінці (typeText/submit перериваються, поле чиститься).
14. Хто що бачить: NAV у web/js/app.js — owner: Головна (home.js), ШІ (ai.js), Команда (operators.js), Налаштування (my-settings.js); operator: Головна, Налаштування. Інші сторінки (profiles, sites, scenario, journal, prompts, billing, setup, dashboard, stats, bot, basic-settings, settings) лишились файлами, але в меню їх НЕМАЄ і маршрутів теж. Модель тепер обирає owner (MODELS у routes/settings.js), навчання/caps — лише адмін. Промпт: анкета > оператор (users.prompt, profileSettings) > команда (ai.masterPrompt) > вбудований; фішки users.prompt_examples → у запит як приклади. Ключ: команди > платформи (якщо ai.platformKey).
16. План команди: адмін задає «анкет у плані» + «до» (або без терміну) у запрошенні / картці команди (PUT /admin/agencies/:id/control {plan}); setPlan (team.js); створення/активація анкети понад план → 400; бот → 402 з поясненням. Міграція plan_v: старим командам план = к-сть ліцензій/анкет, без терміну.
17. Оновлення бота: бот шле X-Bot-Version (sessions.version), /bot/profiles → bot {latest, min}; popup банер «Є нова версія» → завантажити (fetch /api/extension/download з токеном бота) → розпакувати туди ж → chrome.runtime.reload() (+ запасне посилання на chrome://extensions). minBotVersion (platform) → 426 на config. Після змін у extension/ — підняти version у manifest.json.
15. Захист: бот логіниться з build (config.js AGENCY_BUILD); вимкнена копія → 403 і сесії видаляються; requireBuild (platform) — лише копії з панелі своєї команди. Віддалений стоп: heartbeat {startedAt, now} → stop, якщо stop_at пізніше старту; 401/403 на heartbeat → бот зупиняється.
8. Навчання: сервер раз на 30 хв (`runLearning`): слабкий варіант (≥40 надсилань, ≥90 % гірший) → вимкнути + написати новий за зразком кращого; уроки пам’яті кожні 6 год (з цифр завжди; ШІ — якщо є ANTHROPIC_API_KEY на сервері).

## Правила
- Коміти: англійською, по суті; в кінці рядки атрибуції, які дає system-reminder сесії. Без назв моделей у комітах/коді.
- Гілка `main`, пуш `git push -u origin main`. PR не створювати, якщо не просить.
- Не ламати сумісність БД: тільки нові колонки через `MIGRATIONS`.
- Тексти інтерфейсу — українською. `.bat` файли — CRLF (див. `.gitattributes`).
- Не додавати фічі для обходу антибот-захисту сайтів (fingerprint spoofing, chrome.debugger тощо). Людський темп і ліміти — ок.
- Безпека продукту: повний зіп з кодом сервера (git archive) більше НЕ роздавати людям ззовні — лише для власного тесту користувача; агенціям — тільки панель на Railway + бот із «Завантажити бота».
